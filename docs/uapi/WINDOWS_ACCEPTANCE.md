# U-API Connect Windows 真机验收

这份清单用于发布前的最后验收。GitHub Actions 只能证明安装骨架和自动化测试通过，不能代替真实 Codex、真实凭证库和真实服务对话。

## 测试环境

- Windows 11 x64，使用普通本地用户或普通 Microsoft 账户用户；不要使用管理员账户绕过权限问题。
- 已安装并能单独打开官方 Codex Desktop。
- 准备一个专门用于验收的 U-API 密钥。不要截图、录屏或复制诊断信息时暴露完整密钥。
- 从本仓库 GitHub Release 下载 `UAPIConnect-<版本>-windows-x64-setup.exe`，并核对同一 Release 中的 `SHA256SUMS`。
- 运行 `Get-AuthenticodeSignature .\UAPIConnect-<版本>-windows-x64-setup.exe` 并记录结果。`Status` 为 `Valid` 时核对签名者；未签名时 SmartScreen 提示属于已知发布限制，但必须记录实际提示和绕过步骤。

## 首次安装与配置

1. 从 Windows“设置 → 应用 → 已安装的应用”确认此前没有残留的 U-API Connect。
2. 安装 U-API Connect，确认不要求管理员权限。若系统缺少 WebView2，安装程序应先通过微软 Evergreen bootstrapper 自动补齐，再写入 U-API Connect。
3. 检查桌面和开始菜单中的“U-API Connect”与“U-API Connect 设置”两个入口。
4. 打开设置，确认能识别 Codex Desktop，界面没有空白、闪退或横向溢出。
5. 填写验收密钥并测试连接，确认能返回候选模型；保存后输入框必须清空，只显示脱敏尾号。
6. 启动 Codex，完成一条真实 Responses 对话。仅看到模型列表不算通过。
7. 退出并重新打开设置，确认配置、模型和脱敏状态仍在，普通 `settings.json` 中没有完整密钥。

## 2026-09-04 Codex 客户端兼容回归

记录 Codex“关于”页的完整版本号，不能只写“最新版”。候选安装包需记录 Actions 构建编号，旧包不会自动包含修复。

1. 分别从旧版 `requires_openai_auth = false` 配置、已经手工改为 `true` 的配置覆盖升级。不重填密钥，经 U-API Connect 启动后应生成 `true`，真实对话不再返回 401。不要上传完整配置或请求头。
2. 原先语言已经设为 `zh-CN` 但页面仍为英文时，重启后确认侧栏、设置和新建任务页实际显示中文。允许首次兼容处理自动刷新一次，不允许反复刷新。
3. 选择 **`gpt-5.6`（无后缀）**，确认仍以该模型名发出请求，原生推理菜单能选择 Max 和 Ultra；各发送一条短对话，确认不是仅菜单可点、服务端却拒绝。
4. 若有 `gpt-5.6-luna`，确认不能因补丁额外出现 Ultra；其他未知模型不应被批量补上 Max／Ultra。
5. 切回官方模式并通过 U-API Connect 重启，确认本次增加的推理显示设置恢复；用户后来自己修改过的设置不应被旧值覆盖。
6. 确认仍没有广告、额外 Codex++ 菜单、主题、宠物或用户脚本。若状态显示“中文和推理菜单兼容处理尚未就绪”，不得按完整通过验收。

上述项目需要 Windows 真机确认；Rust/模拟页面测试不能代替这一项。

## 运行中变更

1. 保持 Codex 正在运行，重新保存密钥或刷新模型。
2. 确认主按钮明确显示“重启 Codex”；点击后旧进程退出，新进程启动，新配置生效。
3. 切到官方订阅，点击“重启 Codex”，确认进入官方登录或恢复原官方账号，并完成一条真实对话。
4. 切回 U-API Connect，再次重启并完成真实对话。
5. 断开网络后点击启动。已有有效缓存时不应长期卡住；记录从点击到 Codex 窗口出现的时间。

## 窗口、升级与异常恢复

1. 连续点击两个快捷方式，确认不会出现重复后台实例，已有窗口会被恢复到前台。
2. 最小化、关闭到托盘后再次打开设置，确认窗口可见。
3. 安装同版本或下一版本覆盖升级，确认正在运行的 launcher/manager 能被安全替换。
4. 临时重命名或移走 `~/.codex/config.toml`，再次启动，确认能用已保存的安全凭证和模型档案自动修复，不要求重输密钥。
5. 将 U-API 自身的 `settings.json` 改成无效 JSON，确认程序拒绝覆盖并给出可诊断错误；恢复文件后应可继续使用。

## 系统卸载

1. 先切回 U-API Connect，保持已有配置，然后从 Windows“设置 → 应用 → 已安装的应用”执行卸载。不要直接运行安装目录中的卸载器代替这一步。
2. 确认安装目录、桌面/开始菜单快捷方式、URL 协议和卸载注册表项均已移除。
3. 直接打开官方 Codex，确认不再指向 U-API Provider；有官方登录快照时应恢复，否则应进入正常官方登录流程。
4. 检查 Windows 凭据管理器，确认 U-API API key 与官方快照主密钥条目已清理。
5. 确认用户原有的其他 Codex 配置没有被整文件删除。

## 建议补测

- 中文用户名、带空格用户名、OneDrive 桌面。
- 125%、150%、200% DPI 与双屏。
- Windows Defender、SmartScreen 开启状态。
- WebView2 缺失的干净虚拟机。联网安装应自动补齐；断网安装应明确失败，且不能留下新的应用文件、快捷方式或卸载注册表项。
- WebView2 损坏的虚拟机。先确认安装程序不会假装成功，再按提示从微软官方渠道修复。
- 安装、升级、卸载过程中断电或强制结束进程后的恢复。

验收记录至少包含系统版本、Codex 版本、安装包 SHA-256、通过/失败步骤和脱敏诊断日志。任何真实密钥、`auth.json`、完整请求头都不得进入 Issue 或 CI 日志。
